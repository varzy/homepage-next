# PRD

## 迁移 s.ee 图床的图片到 R2

我正在将此前托管在 s.ee 上的图片迁移到 cloudflare r2 上，已经做了许多工作。

但由于之前你写出的一些 bug，导致 scripts 目录下目前出现了很多临时脚本文件。现在，云端 notion 数据库中的数据有很多无法对齐的情况，大部分页面的图片已经改为了 r2 对象存储的地址，例如：https://img.varzy.me/images/posts_39adc9c0-364a-8080-b388-dcdc44f78d56_86fbf62b27866fa4.jpg，但依旧存在一部分图片是托管在 s.ee 平台（该平台以前叫做 sm.ms）的。

现在，我希望从头开始设计这套迁移流程，而不是在原有的基础上缝缝补补。

首先我要明确目标：

1. 将各个 Notion 数据库中的页面中的图片，全部迁移至 r2 对象存储，即，原始的 Notion 数据库的源数据要变更，而不是在客户端通过修改 cdn base url 的方式来实现
2. content.prod 是目前真实的线上数据的备份，由于 notion api 存在调用次数限制，我们最好从这份备份数据中获取原有的 s.ee 平台的图片链接

目前我的想法分为以下几步：

1. 清空现有 r2 存储桶中的所有图片，保持不会被干扰
2. 从 content.prod 中遍历并下载所有生产环境正在使用的 s.ee 平台的图片地址，或者直接调用 s.ee 的 api（https://s.ee/docs/zh-CN/api/GetFileHistory/），将所有 s.ee 平台的图片下载到本地
3. 将这些图片原封不动的按照原路径上传到 r2，例如：https://i.see.you/2026/05/21/jZf0/blog_kotoba_35edc9c0_35fdc9c0-36.webp 在 r2 桶中的路径将是 /legacy/2026/05/21/jZf0/blog_kotoba_35edc9c0_35fdc9c0-36.webp。相比于之前添加了 /legacy 的前缀
4. 图片全部上传完毕后，遍历 Notion 数据库页面，找到所有图片，并将其 url 地址中的 https://i.see.you (可能存在其域名，如 cdn.sa.net 等) 替换为 https://cdn.varzy.me/legacy （cdn.varzy.me 是该桶的域名）
5. 至此，Notion 数据库中所有的图片迁移完毕。重新执行 pnpm sync:all 命令重建本地 content，直至本地也重建完毕

在这整个流程中，会通过数个脚本来幂等的执行这些操作，例如从 s.ee 平台下载图片时，需要有一定的本地对比机制，保证已经下载到本地的不会再次下载一遍。如果脚本因为网络波动等原因中断了，我可以直接再次执行该脚本直至彻底成功。

## 迁移以后的图片

在本次迁移完毕后，我希望未来有新的 notion 页面更新时，执行 pnpm fetch:posts 后，页面中的图片会上传到 r2 并替换 notion 中的原始图片，就如同现在上传到 s.ee 一样。但其路径将会是全新的格式。

我目前的想法是： `/{year}/{month}/{database_label}/{page_id}/{图片hash或block_id}.{扩展名}`。举例：

```plain
https://cdn.varzy.me/2026/08/posts/458e1ef3-2339-4cd1-894b-a8fade2e6bd9/3bcdc9c0-3.png
```

但我不清楚这是否是最佳实践？
